# Story 1.2: MCP integration for live product listings

## Status

In Progress

## Story

As a sourcing user,
I want the system to retrieve live product listings when my chat requests require product data,
so that I can view current offerings with trustworthy supplier information directly from the chat experience.

## Acceptance Criteria

1. The AI/Backend can invoke the MCP layer when product data is needed based on the user’s query.
2. MCP performs scraping/crawling/API calls to fetch real-time product listings and returns structured results.
3. Returned results include optional supplier trust metrics when available (e.g., years active, reorder rate, verification badges); missing fields are omitted gracefully.
4. The API/AI layer formats MCP responses into a normalized product artifact structure for UI rendering.
5. Errors, timeouts, or rate limits from MCP are handled gracefully with informative messages and fallback behavior.
6. The integration is designed to be source-agnostic (future multi-source support) and does not persist product data in the internal DB.

## Dev Notes

- Data Models
  - No internal product tables. Product data is transient and fetched live via MCP. [Source: prd.md#data-models]
  - Normalized Product Artifact (example fields): title, priceRange, moq, supplierName, supplierUrl, rating, buyerInterest, trustMetrics? (yearsActive, reorderRate, verifiedBadges[]), retrievedAt. [Source: prd.md#product-artifact-display, prd.md#supplier-trust-metrics]

- API Specifications
  - Backend orchestrates calls to AI layer which triggers MCP when product data is required. [Source: architecture.md#2.-data-&-request-flow]
  - MCP layer is responsible for crawling/scraping/API calls and returns an aggregated list. [Source: architecture.md#mcp-layer]
  - Results should be normalized for UI consumption, independent of source. [Source: prd.md#product-artifact-display]

- Error/Resilience
  - Handle MCP performance risks: timeouts, rate limits; consider layered caching hooks (future). [Source: prd.md#risks-and-mitigations]
  - Confidence scoring for potentially hallucinated/uncertain data. [Source: prd.md#risks-and-mitigations]

- Constraints
  - Serverless-first; use Next.js API routes. [Source: architecture.md#4.-key-architectural-decisions]
  - Do not persist product data; only chat history is stored. [Source: architecture.md#data-layer]
  - Prepare for multi-source support (Alibaba, Amazon Business) but keep current implementation generic. [Source: prd.md#future-enhancements]

- File Locations
  - Backend integration under `app/(chat)/api/chat/` or corresponding `lib/ai/tools/` for MCP invocation helper as per project structure.

- Testing Requirements
  - Unit test MCP adapter: request/response mapping, error handling, trust metrics omission behavior.
  - Integration test API route flow: when query implies product search, MCP is called and normalized artifacts returned.
